## 已修复内容

1. **思考/回答上下文隔离。** 段落词汇在 `<think>`/`</think>` 处截断。原来的实现中，仅改变最终回答的措辞就可能把同一个思考步骤配到不同的重复步骤。三项回归分别验证回答不能选择思考配对、思考上下文保留、回答不能继承思考词汇。保存数据中未发现已确认的同类跨边界实例，因此不把这个漏洞修复宣称为本轮覆盖增长来源。
2. **显式别名与重复目标名称。** 支持括号里明确声明的多词或带撇号的别名；`X = 完整量名 = 运算 = 结果` 中与目标相同的名称是标签，不再误判为复制操作。其他量的复制与包含自身的算术仍保留。
3. **实际打印的文字算式。** 识别 `plus`、`multiplied by` 等运算词及 `is/equals` 结果关系；支持同一行明确写出的公式、其操作数说明和完整数字代入。绑定只使用原文中的实体和完整运算结构，不从 DAG、金标准或数值相等反推。
4. **原始计算与取模阶段保持一致。** `q = 15 + 10 = 25 mod 23 = 2` 和拆成两句的写法均保留原始结果 25、取模结果 2；显式同余写法同理。没有打印原始结果的 `q = (15 + 10) mod 23 = 2` 仍只有一步。补全逗号连接以及 `mod 23 is 2` 等明确的紧邻取模表达。
5. **用全数据审计发现并修复了一处新增回归。** 初版局部代入检测可能扫描到后文的 `is`，吞掉原本已识别的 22 个旧轨迹结果；已优先识别直接数字代入并限制操作数句法，加入两项复现测试。最终数据不再有这些漏项。

匹配排序和最优路径强制配对规则保持原逻辑；解析/上下文版本标记升级为 `printed_expression_views_forced_sequence_v7`。没有降低 50% 门槛，没有删除重复思考步骤，也没有把未匹配单元变成「无变化」。

## 分母与配对审计

`audit_recovery.py` 按实体和原文结果位置比较前后事件，按原始测量单元对照支持情况。两批数据均验证：

- 原始文本、token IDs、offsets、答案、正确性和生成状态逐项一致。
- 先前合格的思考结果位置丢失数为 **0**；先前合格的测量单元丢失数为 **0**。
- 审计计数与生产测量报告的分母、匹配支持、共同噪声支持完全一致。

| 固定原有分母的诊断（不是主报告替代指标） | 旧数据 | 新 pilot |
|---|---:|---:|
| 原有测量单元 | 9064 | 483 |
| 原有单元匹配支持：前 → 后 | 4212 → 4370 | 234 → 249 |
| 原有单元新获支持 / 失去支持 | 515 / 357 | 30 / 15 |
| 原有单元共同噪声支持：前 → 后 | 3374 → 3551 | 200 → 210 |
| 新恢复的测量单元 / 其中匹配数 | 1182 / 586 | 62 / 30 |

恢复步骤和修正阶段会改变序列中的最优路径，因此旧配对有新增也有失去，收益不是单调的。完整主指标仍采用包含全部新步骤的分母。审计保存新增/重分配配对的双方原文与算法证据；已查看 pilot 的 70 个此类合格配对的文本和阶段，但这不是独立人工标注的匹配准确率，尤其不能把「最优路径唯一」当作语义正确的证明。

## 仍未解决的瓶颈

新 pilot 的 266 个缺失单元包括：148 个顺序/上下文冲突、60 个重复步骤歧义、43 个阶段不兼容、8 个表达式不兼容、7 个没有同实体候选。这些是对当前解析集合的算法诊断，并不证明所有原文步骤都已经被找全。

最差题 `igsm-official-0008-op5`：基准有 53 个已解析思考步骤，两个无关前提扰动轨迹分别有 24、28 个；匹配 27/106 = 25.47%，共同噪声支持 11/106 = 10.38%。只考虑实体数量的一对一乐观上界为 `(24+28)/106 = 49.06%`，还未施加运算、阶段、顺序和歧义约束。**在当前事件集合和现有两条扰动轨迹下，仅放宽配对算法也不能让这题达到 50%。** 这不是对完整原文召回率的上界。

原文可见基准轨迹多轮重复验证，并比较「逐步取模」与「整数计算后取模」两条路径，扰动轨迹没有同样展开。不能强行把基准的每次检查复用到同一个扰动步骤，也不能删除基准的反复推理以抬高覆盖率。

后续需要对这些重复轮次/备选计算路径建立可核对的原文标注，测清遗漏与真实缺失各占多少；若确认某轮推理在对应轨迹中不存在，应报告缺失。增加同条件自然扰动与噪声重复采样可作为单独预登记的覆盖实验，必须保留本轮结果作基线，不能事后混样改写原实验已通过。若研究目标允许改变自然步骤的分析单位，应明确注册新估计对象，并与旧自然全步骤结果分开报告。
