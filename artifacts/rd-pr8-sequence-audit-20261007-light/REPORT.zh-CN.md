## 已修复的代码问题

1. 行首 Markdown 项目符号不再被当成操作数运算符。配对粗体/代码标记只按版式遮罩，保持原文长度和 offsets，不能破坏 `2**3**2` 等乘方语法。
2. 支持保存编辑轨迹中的粗体变量、带等式 RHS 的反向实体声明、明确实体主语后的跨行 `So:` / `Let me write that as:`。不跨段落继承主语，不从另一赋值 RHS 推断新实体，不使用数值或标准答案映射变量。
3. 原匹配器要求每个结构锚点在两侧各出现一次，导致重复计算全部丢失。新版本在每个区域的完整事件序列上保留所有最优单调匹配共有的事件对；重复结构还需要另一个实体的共有对应。多个可能对应、孤立重复确认和阶段/结构不兼容仍未知。主比较、噪声和 C2 共用此规则，保存方法及配对依据。
4. 未匹配事件原先从 JSON 身份字符串截取 `node_id`，丢失已知任务依赖标签。现在保留 reference 事件的真实节点；只在编辑轨迹出现的事件不伪装成 reference 事件，未知行为不变成负例。
5. 小 pilot 的相关事实从目标 DAG 祖先中登记；离线重测精确选取同样的 seed-0 编辑与 seed-1/2 噪声，检查缓存缺失和重复。新增 `--report-only`，只导出报告及来源记录，不重复复制大体积派生产物。

匹配版本为 `region_structure_forced_sequence_v3`。它仍假设区域内步骤顺序保持。在这一假设下唯一的对应，不等于经过人工验证的语义步骤身份。序列算法测试不能提供真实配对 precision/recall，报告继续保留 `parser_recall=not_estimated_without_annotated_steps`。

## 为什么还不能再跑一天

剩余问题是主测量的可识别性：自然推理在编辑和重新采样后可能改用表达式、调整次序、重复确认，原事件不一定有可确认的反事实对应。修复 Markdown 不能解决这一点，按出现次数或数值硬配会制造标签。

先用现有 base/edit/noise 原文建立人工配对审计，分别覆盖重复确认、计算阶段、阶段变化和策略重排，检查匹配依据并区分无法识别的情况。开发时选取的错误片段不算独立验证集；在独立审计确认步骤定义和配对可靠后，再执行不生成 token 的登记缓存检查。当前已有 24/24 编辑，失败不是少下载缓存导致的。

若自然轨迹无法支持原定义，需要明确调整实验协议，例如另设带固定步骤标识的结构化生成条件。这会改变条件，必须单独登记，不能宣称原自然生成实验已经被修复。当前 PR 提供可复核的代码修复和失败证据，**不宣称主实验就绪，也不对论文 claim 作肯定或否定结论**。
