# PR8 后续修复：声明解析与共同支持统计

有可继续修复的工程问题，不能把所有缺失都归因于模型策略变化。本次补丁修复了一个真实 base/edit 配对中的声明差异，并把部分共同支持的描述统计与原有整条轨迹 rho 分开报告。主测量仍未通过，不启动新生成。

## 已复现并修复

保存原文中存在这种声明：

```text
9. The number of Temperate Evergreen Forest's Organs equals (...). So:
   - TEF_Organs = TEF_Starfish * Starfish_Organs = 18 * 3 = 54
```

解析器已支持跨行 `So:`，但未允许变量前的项目符号，导致 base 中 `TEF_Organs` 在首次使用时仍未解析。edit 恰好在同一行另有 `So TEF_Organs = 8`，因此可以解析。随后两边完全相同的 `RF_Seahorse = 4 + TEF_Organs = 4 + 8 = 12` 得到不同表达式身份，被误报为不可配对。

现在明确引入语后可接行首项目符号，保留原文 offsets、声明生效位置和歧义规则。来自真实两条轨迹的原文与来源哈希保存在 `tests/fixtures/pr8_bulleted_declaration_pair.json`。修复前，该回归复现 `unresolved:tef_organs` 与真实节点身份的差异；修复后两边一致并可匹配。

## 部分共同支持不等于整条轨迹满足条件

原有 rho 要求所有用于 raw 密度的观测事件都有噪声支持；只要一个事件缺失，整条轨迹返回 null。因此 1/24 条有 rho，不能解释为只有一条轨迹拥有任何可用数据。

新增 `common_support_diagnostic`：仅在 edit 和 noise 同时可用的事件上，以相同事件权重并列保存 raw、noise 和 signed excess，另报事件数、格数、相对已观测事件的覆盖率。共同支持为空仍为 null。它描述的是选择后的子集，不能代表未匹配事件或证明因果依赖。

旧 `rho`、P1 输入、缺失分母、50% 检查以及启动条件均保留。该描述统计不会让失败的运行通过。回归还检验了格数不等时事件权重一致、负 excess 保留以及部分支持不改变门槛结果。

## 建议的修复路线

1. 继续用现有 base/edit/noise 原文建立配对审计，明确区分漏解析、变量声明不一致、阶段不同、重复确认和真实策略改变。审计不能只看覆盖率，也要验证对应是否正确；开发时选中的错误片段不能作为独立验证集。
2. 对自然推理，只合并有明确语义依据的表达形式。按打印出的操作数关系和上下文区分初次计算、模运算、核对与修正；无法确定步骤身份的情况保留未知。不得按数值、答案、相同出现次数或最近位置补配。
3. 若自然轨迹始终没有稳定的全步骤对应，另设受控的明确提交步骤条件，先验证解析、标签和干预链路。固定步骤标识必须伴随明确的步骤语义，单独加序号不能解决问题。这个条件改变了生成协议和测量范围，需独立登记，不能冒充自然条件的成功。
4. 在定义和配对经过独立验证后，再决定是否将共同支持上的量登记为新的分析指标。当前只保留为描述诊断；不能为了让 rho 非空而悄悄替换主指标。

这条路线可以继续检验方法是否可测量，不能保证论文主张最终成立，也不能保证原自然条件的所有步骤都能识别。此次代码修复没有改变生成条件。
