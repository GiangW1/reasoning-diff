## 本次实际修复

1. 自然提示在题目派生成句子级前提后丢失：新任务保存提示版本，旧任务保留原提示；混合版本阻止测量通过。
2. 自然等式链只取一种表达式，漏掉 `mod23`：保留实际打印的表达式视图，规范化加法/乘法顺序；不从答案或任务依赖推导缺失表达式。
3. 声明遗漏及错误归属：补括号内 `let's denote/call this`、明确话题内的数量缩写、显式 prose scalar/copy；阻止 `Sum1`、不相干话题和后续泛用声明误赋身份。
4. 跨行吞入别的赋值：`Substituting the value of Swan_Pons:` 不能跨空行把 `Peacock_Pons = …` 当成 Swan 的值。
5. 模余数阶段混淆：明确标注 residue 的 scalar/copy 与未标注标量分开；不根据数值是否相同决定匹配。
6. `--mode pilot` 在配对后退出；保存每条请求和配对表。新增 `reparse_pr8.py --pilot`，验证任务、seed、原始请求与保存总表一致、完整题目集合及源文件哈希，重算不调用模型。

一个直接复现：0007-op21 的 seed 2 在生成版本只识别到 1 个事件；括号声明修复后识别到 77 个，原文及边界不变。全套 **513 项回归通过（126.01 秒）**，compileall 和 whitespace 检查通过。

## 仍然阻塞的原因

单次推导提示没有让模型停止所有复查。有些 base 反复演算、探索另一种取模顺序，编辑轨迹没有对应的同一次演算。当前解析集合中，0008-op5 的 base 有 34 个 thinking 计算/提交事件，两条干扰编辑分别只有 12、19 个。即使忽略顺序、表达式和歧义，按实体的一对一数量上界也只有 **31/68 = 45.59%**；这个集合无法仅靠换一个一对一匹配算法达到该题的 50%。这是对**现有解析事件集合**的上界，不是对所有未解析自然语言的上界，不能据此宣称解析召回率 100%。

同一算法对旧保存的 335 条轨迹重算为 **3639/7713 = 47.18%**，共同噪声支持 **2995/7713 = 38.83%**，完整 ρ 为 0/24。旧数据与新提示数据分别报告；不能把本次新提示的 52.19% 回填成旧轨迹结果。

匹配中的“所有最优路径共有”是算法证书，不是人工语义准确率。此次没有独立人工标注集，也没有证明完整原自然全步骤方案已经成功。后续若继续坚持自然全步骤目标，需要进一步验证生成中的重复演算对应关系；本次授权的 GPU pilot 已结束，未擅自追加生成。
