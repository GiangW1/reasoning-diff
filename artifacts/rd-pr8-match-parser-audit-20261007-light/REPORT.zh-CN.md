# PR8 自然轨迹匹配：解析修复与仍未解决的覆盖问题

本次目标是解决自然轨迹匹配覆盖不足。结论：发现并修复四项确定的解析错误，但**匹配覆盖仍未达到现有检查要求，目标尚未完成**。没有修改匹配规则、降低阈值、将未知标签改成 0，或把受控数量提交条件当作自然全步骤实验。

## 已修复的错误

1. 声明检测分为逐行、跨行两遍。代码先发现后面的同名声明后，会忽略跨行检测发现的更早声明，导致早期有效赋值全部漏掉。现在同一实体取原文中最早的明确声明位置；真正冲突的声明仍未知，声明之前的赋值仍不回填。
2. `Entity: X = ...`、`Entity: Let's call this X = ...` 等没有项目符号的明确变量定义未登记，后续使用该变量的事件因此漏解析。现在读取这类明确名称绑定，不按答案或数值猜测实体。
3. `Entity: X = 3` 的实体全称和缩写可能被算成两个事件。现在同一实体、作用域和同一原文数值跨度只计一次；保留整句起点，使用内层赋值的表达式结构。不同位置的重复计算仍保留为不同事件。
4. 原始数据含 1279 个 `≡` 和 255 个 `\equiv`（统计整个生成文本）。此前不能读取 `q = 20 * 5 = 100 ≡ 8 (mod 23)` 中明确写出的余数。现在提取 8，标为 reduction，仍不代替模型计算未写出的余数。

新增 12 项回归，先复现对应错误再修复；全量 442 项通过。实际 tokenizer/model forward、真实 smoke 和新的 GPU 生成均未运行。

## 为什么不能继续靠放宽匹配解决

现有数据中的两条完整自由推理会复算不同次数，甚至采用不同计算阶段。一个 reference 事件可能对应另一条轨迹的多个复算位置，也可能根本没有对应步骤。全称、缩写和已打印等式的解析可以修复，但这些修复不会创造缺失的步骤身份。

例如一边出现两次同结构的 `q = ...`，另一边只有一次，在没有独立上下文时有两个同样合理的对应。取第一次、最后一次、最近位置或相同数值都不是身份凭据。现有匹配器因此继续保留未知；本次没有修改它。

开发时另外试算了“保留等式链中明确打印的中间结构”和“只在所有最优匹配均给出相同变化结论时确认结果”的方案，也没有使全部检查通过。这些未验证的试算没有接入生产标签或作为实验结论。

## 后续必须区分的实验定义

保留原来的整条自由推理效应，就必须继续承认这批数据存在不可识别的对应，不能保证修代码后达到指定覆盖率。现有 `quantity_steps` 则是单独登记的受控数量提交条件，尚无真实模型验证。

另一个待用户决定的方案是新增共享推理前缀的配对续写：保留生成历史，在相同局部起点改变题目前提，并配置相同历史的无编辑噪声对照。这测量给定历史后的局部依赖，历史里已经传递的前提信息被固定，不能替代完整重新推理的总效应。共享前缀也不自动保证输出可解析，仍须如实记录失败并经过小规模真实验证。该方案本次未实现、未生成数据，不计入覆盖改善。
