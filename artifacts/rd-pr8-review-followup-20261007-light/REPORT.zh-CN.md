# PR8：9206685 复核后的两项修复

桌面附件检查的是旧提交 `241cd31`。服务器另有针对 `920668517845239fe9771f9a356dd668114fa1eb` 的 CPU 复核，确认最新版仍有两个代码错误。本次修复这两个错误，没有启动真实模型 smoke 或 GPU 实验。旧自然条件仍未通过测量检查，新受控条件尚未得到真实模型验证，不能据此启动未经检查的正式生成。

## 多卡格式失败被覆盖

三卡 pilot 的轨迹 ID 在各 worker 内从 `trace-base:0:seed0` 开始。原汇总用 trace ID 作字典键，9 条轨迹只保留 3 条格式记录。服务器复现中 GPU 2 的 seed 0 格式无效，后续 GPU 的同名有效记录覆盖了它，使格式检查错误通过，并试图启动三个配对 worker。

修复为逐轨迹列表，保存题目 ID、轨迹 ID、seed 和格式检查结果，并检查每一行。回归分别将无效轨迹放在 GPU 2、3、6，均保留全部 9 行、准确报告失败位置，并在新增配对生成之前停止。各配对 worker 内的 ID 本来唯一，不改动其已有报告结构。

## C2 误把旧数值计入续写

Qwen tokenizer 可以把相邻 `</step><step` 中的 `><` 编为一个 token。下一个 step 的 `pre_step` 排除跨界 token 后，前缀已经包含上一数量的完整 `<commit>4</commit>`，但还缺 `</step>` 的最后一个字符。原代码只检查事件结束位置超过切点，因此将旧节点 `r` 与新节点 `q` 都计入续写，可能虚增非目标保留率。

解析仍保留完整上下文，但评分现在要求 `value_start >= cut`：数值必须从续写部分开始。仅补齐闭合标签、或数值已部分进入前缀时，都不重新评分该结果。真实 Qwen tokenizer 的相邻、换行和空格三种边界已保存为 CPU 回归 fixture；额外检查数值恰在切点开始和已消费一个字符两种情况。
