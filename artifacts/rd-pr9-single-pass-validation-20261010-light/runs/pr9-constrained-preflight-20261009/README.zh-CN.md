## 解码器实际做什么

在一个持续的自回归流中固定 thinking 边界、节点 ID、step/commit 标签和最终 boxed 框架。每个节点的文字推理和提交数值由模型采样；最终答案也独立从模型 logits 采样，不复制标准答案或节点真值。

每节点文字达到 512 token 时要求模型提交整数，并记录触发次数；整数语法允许符号和最多 12 位数字，不按正确值或模数范围过滤。结构 token、文字预算触发次数、数字采样 token 数逐轨迹保存。没有按节点重启推理、追加采样、重试或在总预算耗尽后补闭合标签。总预算截断仍失败。

P3 和 C2 从保存前缀恢复相同语法状态；干预和基线分别复制状态，不以改变采样条件制造差异。继续保留 BF16 范数校准及独立完整格式检查。

## 如何解读

格式及 ID 覆盖率高是约束的构造性质，不是模型能力提升的证据，也不是自然匹配的成功率。必须另查 ID 所指数量和块内计算是否一致、单次噪声敏感性、任务正确率、预算触发情况和真正的行为响应。旧条件失败和新条件结果分别报告。

全部参考格式通过后才扫描比较条件，全部比较格式及分层 95% 测量门槛通过后再拟合/干预。即使全流程完成，仍可能因正确/错误标签单类、方向不可估计或效应不明显而无法支持研究假设。
