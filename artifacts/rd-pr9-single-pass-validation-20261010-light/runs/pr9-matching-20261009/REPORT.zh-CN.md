## 实际修改

1. 避免把 `q = 完整源名称 = 3` 中已知的目标 q 错误地重命名成源实体。
2. 识别明确主题后的 `Let me write that:` 等记号引入；不跨段落继承主题。
3. 在右侧表达式中识别唯一、约定式的实体缩写；有多个候选时保留未知。
4. 保留原有有序匹配，按同实体、作用域、生成区域恢复明确运算的局部配对，允许不同实体叙述换序。不得跨越已匹配的同实体锚点，不恢复纯标量确认或含未解析名称的表达式。
5. 导出恢复证据、未匹配原因和固定队列审计。没有修改 rho 定义，没有删除困难参考事件，没有扩大样本预算。

## 剩余问题及鲁棒性

自由推理会换说法、换顺序、拆步、合步、重复确认、采用不同计算路径。前两类可以改善解析和结构匹配，后几类可能没有逐事件的一一对应。对每种表述补规则不能保证泛化，必须允许未知，不能通过比较答案值或标准解来决定配对。

对 36 个 reference/noise 对，以当前解析事件集作诊断：

- 合格参考步骤共 1389，当前匹配 601（43.27%）。此处是步骤计数，不是上表带前提维度的单元计数。
- 保留现有实体/阶段/表达式兼容条件，但完全忽略顺序和歧义，最大二分匹配只有 804（57.88%）。这是宽松的组合上限，不是可接受的实际匹配率。
- 进一步仅保留同实体、作用域、区域的容量约束，忽略阶段和运算，最多 994（71.56%）；30/36 对仍有数量缺口。这种宽松匹配会容许错误阶段配对，只用于说明数量差异。
- 上述上限**仅适用于当前解析出的事件集合**，不能证明原始文本不存在未识别的对应，更不能推广为所有自然推理的理论上限。
- 训练集例子 `igsm-pr9-20261008-0052-op5::noop:front:high`：参考解析出 51 个合格步骤，兼容无序匹配最多 14，同实体容量最多 18。实体 `p_0_0_2_0` 参考有 23 次、noise 中只有 1 次；需结合原始文本检查重复确认与漏解析，不能直接把这 22 次差额归因于模型省略。

因此，现阶段不能承诺完全自由推理的逐步指标在单次生成下全部可用。更稳健的候选方案是预先定义稳定的测量单位并试验明确的实体/阶段输出标记；这会改变生成条件，必须单独验证，不能包装成旧自然推理指标已经修复。如果必须保留自由文本，则需要评估带未观测区间的结论或明确弃权，不能强填缺失值或只报告容易匹配的子集。以上两条均尚未作为新实验实施。

- CPU 全套测试：**683 passed in 90.06s**。包括新加入的解析、乱序、重复歧义、值/标准解不影响配对、固定参考分母和 checkpoint 防篡改测试。
- 486 次比较中，恢复逻辑保留了仅解析修复版本的全部已有配对；所有配对证书满足一对一。

- 对所有含新增配对或噪声对照的 220 次比较检查了兼容性、区域、实体和同实体顺序约束。
- 查看了前 20 个 train/dev 恢复配对的表达式文本，包括名称复制、乘法和缩写变体；这只是实例检查，**不是独立人工标注的语义准确率，也不是全部 322 对的语义审查**。
