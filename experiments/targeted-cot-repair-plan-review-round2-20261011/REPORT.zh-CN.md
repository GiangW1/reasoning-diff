# targeted CoT repair 方案第二轮独立审查

审查提交：`9af62dcfb7ca9f2dfc17228a0faab7c768a9f631`，父提交为 `f2a374c039c807a974b0cc1becfcfd2f68bde51d`。本轮对比上一轮审查报告，重点检查联合成功指标、比较天花板和分层停止规则。

本次只做静态方案审查和确定性算式核对，没有运行模型、接口请求、smoke test、推理流水线、训练、激活采集、探针或干预，也没有修改实验代码。

## 结论

**可以进入不调用模型的执行准备阶段，但不能直接启动正式实验。** 上一轮指出的候选记录范围、标注隔离、B 边界和任务可区分性问题已经在方案层面补齐。新增的联合指标和分层停止规则能够阻止“定位命中”和“恢复成功”来自不同题时被拼成一个成功结论。

剩余工作主要是实现前验证：冻结题集和静态验证器、用无模型文本例子检查 B 规则、落实两位复核者和匿名封存、确定实际提示包装与结果解析。方案本身仍明确这些工作尚未完成，也没有把静态案例通过写成模型验证。

## 已解决的问题

### 1. 候选记录与根因范围：已解决（方案层面）

上一轮的阻塞项是 Oracle、随机位置和修复器只接受四条记录，而根因可能位于记录外。本版在 §89–97 定义了固定候选集合 `C_i`、根因记录集合 `R_i` 和唯一映射：

- 根因片段先独立标注，再映射到四条固定记录；
- 候选外、跨记录不可表达和映射未知分别记录；
- 这些轨迹保留在 48 条覆盖表和真实错误计数中，但不进入 Oracle/主定位比较；
- 需要超过两条替换的困难题仍保留，不得改名为候选外；
- 随机机会按候选记录去重后的集合计算。

这闭合了接口定义和评分口径。主结论必须明确限定为“候选接口覆盖范围内”。

### 2. 标注盲法和未来信息隔离：已解决（方案层面）

§79–85 将保存图限定为不含模型输出的静态题目图，并隐藏任务 ID、related/neutral 标签、方法和后续分支名称；标注者只看匿名题目、静态图、截至 B 的输出和候选区间。还要求双人独立提交、记录逐字段一致率、分歧保留未知，并禁止把新增模型标注请求藏入 488 次预算。

方案同时承认不能保证标注者看不出题面中的干扰类型，这个边界表述是诚实的，不应再宣称完全盲法。

### 3. B 边界：已解决（规范层面，尚未实现验证）

§50–63 现在规定了首次实际提交、完整句/列表项/表格行、重复记录、跨段假设、实体绑定的提前消费者值和缺失通道的处理。B 的规则在生成前冻结，不能用后缀中的否决或正确答案回推更有利的边界；无法唯一划分或复核者分歧时记为未知。

这解决了“为了达到覆盖率而后移边界”的风险。剩余限制是文本区间重建和真实输出兼容性还没有实现测试，方案要求先用无模型文本例子和后续接口检查验证。

### 4. 任务可区分性：已解决（方案层面）

§59 要求正式题集冻结前枚举参数、正确值、错误候选和 D/I 传播结果，拒绝消费者不敏感、独立分支受影响、碰撞、相消和其他静态缺陷，并保存每次拒绝原因。冻结后不得因模型表现换题或补齐正例。

这把合法预筛与事后按结果挑题区分开了；仍需未来执行准备阶段提供实际验证器和冻结清单。

## 部分解决和边界

### 5. Ls/Lt 提示公平：部分解决，重要边界保留

§116–121 为 Ls 和 Lt 增加共同的三步核查、相同字段、位置格式、触发规则和 256 token 上限，也要求记录两份提示的文本与输入 token 差异。Ls 与 Lt 仍有专项重点差异，这是研究问题本身的一部分。

因此，本轮结果最多支持“来源专项文本提示相对通用文本提示的增益”。它不能单独证明隐藏来源选择机制；方案已经在 §120 和 §260–266 明确这一限制。执行时不能把提示策略差异写成机制因果证据。

### 6. 静态核对：通过纸面案例，未通过实现验证

新 `VERIFICATION.json` 声明 22 个构造检查全部通过，并保留 488 请求预算、896 token 上限、候选外覆盖和未知结果处理。独立复算方案 §194 的两个示例分别得到：

- 6 次命中但没有同题修复，`J=0`、`Δ=2`、`K=2`；
- 两题同题命中、修复并相对 N 恢复，`J=2`、`Δ=2`、`K=2`。

这些检查证明公式和纸面反例相容，不证明解析器、题目生成器、修复接口或模型在短预算下可用。`VERIFICATION.json` 本身也明确了这一范围。

## 联合成功规则审查

§180–194 定义：

- `H_i`：Ls 在修复前冻结的第一位置命中根因记录；
- `P_i`：S_policy 实际执行了合法且正确的补丁；不触发、no-op、只补数字、越界或语义不确定都不算；
- `W_i`：S_policy 成功而 N 失败；
- `L_i`：S_policy 失败而 N 成功；
- `J = Σ(H_i×P_i×W_i) − ΣL_i`，要求 `J≥K`。

这个规则正确阻止以下替代解释：错误位置的恢复不能冒充根因修复；只在命中题上重算不能逃避损失；S_force 不能替代 S_policy；P 未知不能免除损失；同一队列中的定位和恢复不能跨题拼接。因为 `H_i,P_i≤1`，正项是 `W_i` 的子集，所以 `J≤Δ(S_policy,N)`，联合门槛比单纯净增更严格。

一个仍需保持的解释边界是：`P_i` 可以证明文字补丁正确，但即便 J 通过，也不能证明隐状态来源关系被因果改写；方案 §192、§262–266 已明确这一点。

## 天花板和停止规则审查

§227–239 的天花板检查是按每个比较的固定配对集合进行的：

- Ls 对 Lt/Lr 使用 `m−h_B≥2`，不会因为通用基线已经接近满分而错误宣布专项失败；
- O/C 只使用标签阶段冻结的 `Q_C`，要求 `|Q_C|≥8` 且 C_force 至少有两题失败，不借用子集外失败数；
- S/N、S/T、S/Rnd、S/G 的空间分别检查，缺少空间时只将对应优势记为未检验。

§241–258 将测量、自然错误供给、接口覆盖、Oracle 可修复性、位置特异性、来源专项定位、联合策略和损伤分层停止。特别是 N 失败足够但 Ls 未命中待恢复题时，明确归为当前定位修复链不足，不能全部解释成自然恢复天花板。
